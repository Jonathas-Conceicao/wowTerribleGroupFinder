## Top 3 Priority Fixes

1. **Add a secret guard where `area` is consumed** (WARNING) — `UI/Table.lua:481-482` (`RightText`) and `UI/Table.lua:1132-1135` (`FillRow`). Both check `type(...) == "string"` and then compare to `""` or call `:gsub`. A secret string still has type `"string"`, and comparing or gsub-ing it raises a Lua error. `Listings.lua` filters it through `Text()` today, so this is safe for live data, but the contract (D-07: a secret zone silently drops only the zone) and the project rule ("guard reads with `issecretvalue()` where values may be secret") put the guard at the point of use. Fix: reuse the file's `IsSecret` helper (already used at line 540 for the comment) in both places: `if IsSecret(x) or type(x) ~= "string" or x == "" then zone = nil end`.
2. **Zone cap leaves little room at 620 px** (WARNING) — `UI/Table.lua:66, 829`. At the 620 px layout the Activity cell is about 130 px, so the cap is 58 px (about 10 characters). "Orgrimmar" fits; "Stranglethorn Vale", "Eastern Plaguelands", "Blackrock Mountain" and "The Temple of Atal'Hakkar" are all cut, and the comment gets the remaining roughly 66 px. The contract accepts this and the full values are in the tooltip, so it is by design. The cost is that the most common long zones lose their distinguishing end ("Eastern Pla…"). Options inside the spirit of the contract: raise `ZONE_FRAC` to about 0.55 for zones with no comment (the comment is empty, so nothing is squeezed), or keep the cap only when a comment is present. Confirm in game before changing.
3. **Zone and comment greys invert the information weight** (WARNING) — `UI/Table.lua:1175-1176`. The zone (`W.GRAY`, 0.5) is darker than the free-text comment (`W.LIGHTGRAY`) and equal to the Level and the non-matching Activity colour. The contract chose this to keep the two distinguishable without a separator, which works, but it makes the structured, scannable value (where the player is) the quieter one. Confirm in game that the two greys are distinguishable on the row stripe and the hover; if not, add the separator the contract rejected, or lighten the zone one step.

Further issues, lower priority:

4. **First-fill width fallback** (`UI/Table.lua:826-830`, WR-03 skipped in `04.1-REVIEW-FIX.md`). If the cell is 0 wide at fill, the cap is `ZONE_MAX` (100) for that frame, and only the cell's `OnSizeChanged` hook (`:894-898`) refits it. A one-frame wrong width is likely invisible, and `FillRow` refits on every fill, so this is cosmetic. Worth one in-game look at the 458 / 620 px switch.
5. **Zone on solo rows duplicates the solo tooltip line** ("spec, zone"). By contract (D-08), so it is not a defect, but a long solo zone is cut in the row and complete in the tooltip only.
6. **Tooltip width grows with a long zone.** Double lines do not truncate, so "The Temple of Atal'Hakkar" beside a class-coloured name widens the whole tooltip. Contract says "never truncated by us"; acceptable.
7. **`FitZone` early-returns on a hidden zone** (`:821`), so `OnSizeChanged` fires harmlessly on zone-less rows. Correct, noted only because the guard order matters: `Show()` runs before `FitZone` in `FillRow` (`:1139-1140`), which is right.
8. **`Preview.lua` coverage** matches the contract table: leader and members zoned (DM, BRD), some members unzoned (Ellery, Nyx), none zoned (SMGY/SMLIB), long zones (Atal'Hakkar line 214, Stranglethorn line 264), group with comment and zone, solo players unchanged, `P.party` untouched. Member parsing is guarded (`rest and rest:match`, `:82`). A zone containing `:` would not parse, which no sample uses.

## Detailed Findings

### Pillar 1: Copywriting (4/4)
- No new user-facing strings. The row shows the zone name as reported, with no prefix or punctuation (`UI/Table.lua:1138`).
- No placeholder for an unknown zone: the zone FontString is emptied and hidden (`:1143-1144`) and the comment returns to x 0 (`:1145`). Tooltip members without a zone get no right text (`RightText` returns `gs` or nil).
- Zone text is `|`-escaped before the colour wrap (`:482`), so a zone cannot inject colour codes into the tooltip. The row FontString takes the raw name, which is the same escape-safe path as the comment.
- Finding that keeps this from being flawless: none against the contract. The only risk is the escape being applied on the tooltip and not the row, which is correct because FontStrings with plain text do not need it.

### Pillar 2: Visuals (3/4)
- Line 2 of the Activity cell reads zone, 6 px gap, comment (`:1141`, `ZONE_GAP`). Row height is unchanged and no new column or icon exists, as contracted.
- The focal point of the row is unchanged (name and activity on line 1).
- The cap at 620 px (about 58 px, `:829`) cuts most multi-word zones and compresses the comment. Needs in-game confirmation of how it reads. See fix 2.
- Tooltip: the zone is the right-hand text of the existing leader and member lines; no new block or header. Groups over 10 members show only the leader's zone, following Forever's stock tooltip (`:527`).

### Pillar 3: Color (3/4)
- No hex or raw colour in the row: `W.GRAY` for the zone (`:1176`), `W.DELISTED` on greyed rows via the `texts` list (`:1165-1168`), `W.LIGHTGRAY` for the comment (`:1175`). The tooltip uses `ColorCode(W.GRAY)` (`:482`).
- Accent usage: none new, as contracted. The zone never takes the blue or green of line 1.
- Weakness: three separate elements share `W.GRAY` (Level, non-matching Activity, zone) and the zone is darker than the comment. See fix 3.
- Greyed rows: the zone takes `W.DELISTED` like every other text. Zone text is not passed through `Plain()` as the other greyed texts are, but it carries no colour codes in the row, so it renders correctly.

### Pillar 4: Typography (4/4)
- One new FontString, `GameFontDisableSmall`, 10 pt (`:889`), same as the comment. `W.Text` sets left justify and `SetWordWrap(false)`; `SetMaxLines(1)` is set on both zone and comment behind existence checks (`:891-893, 902-904`).
- No bold, size override or new font object. Tooltip uses the stock double-line font.

### Pillar 5: Spacing (3/4)
- Zone at TOPLEFT (0, -19), the same y as the comment (`:890, 900`). Gap `ZONE_GAP = 6` (`:66`). Cap `min(100, floor(cell * 0.45), ceil(text) + 1)` (`:824-832`). The `+ 1` is from the review fix for an exact-fit ellipsis.
- The comment is re-anchored on every fill after `ClearAllPoints` (`:1136-1147`), so pooled frames do not keep a stale anchor.
- Weakness: width depends on `OnSizeChanged` after a width change (WR-03). The cell's measured width is unknown on the first fill.

### Pillar 6: Experience Design (3/4)
- State coverage matches the contract table: zone and comment, zone only, comment only, neither, own row (`not l.mine`, `:1132`), missing or empty zone.
- Review fixes verified in code: own-listing tooltip shows no zone (`:525, 532-534`), malformed preview spec no longer errors, pipes escaped.
- Click, sort, search and hover are untouched; the zone has no hotspot.
- Gap: secret handling is only upstream (`Listings.lua` `Text()`). `FillRow` and `RightText` would error on a secret string if one ever reached them. See fix 1.

### Needs in-game confirmation (not scored)
- Zone at 620 px and in the 458 px stand-in, including switching widths: ellipsis shown, comment not squeezed to nothing.
- Fast scrolling: no stale zone, comment back at x 0 on zone-less rows.
- Greyed rows show the zone in the delisted grey.
- Group tooltip zones right-aligned; zone-less group looks as before; group over 10 shows only the leader.
- Live `areaName` values on solo and leader rows; no Lua error and no taint with `/console taintLog 1`.

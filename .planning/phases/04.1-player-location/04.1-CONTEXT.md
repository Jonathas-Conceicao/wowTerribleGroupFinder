<domain>
## Phase Boundary

Show where listed players are in the world, from the zone the game reports per member
(`areaName` in `C_LFGList.GetSearchResultPlayerInfo`):

- each solo row shows the player's zone; each group row shows the leader's (LOC-01)
- a group's tooltip lists each member's zone where the game provides it (LOC-02)
- the preview sample data carries zones so `/tgf preview` shows the feature

Author's request (verbatim): "show where the person is in the world on the UI. show for the
single player and for the leader when a group (if we have info for the other players when we
mouseover can show for them too)".

Not in this phase: maps, distances, waypoints, filtering by zone, zone-based sorting.

</domain>

<decisions>
## Implementation Decisions

### Where the zone sits in the row
- **D-01:** Second line under Activity, not its own column. At 620 px with Gear Score off,
  Activity spans x=284 to about 151 px from the row's right edge, roughly 130 px; a zone
  column wide enough to read (80 px or more) would leave Activity about 50 px. The proposed
  fallback ("a second line under Activity if a column does not fit") applies.
- **D-02:** The second line under Activity already holds the comment. The zone becomes its own
  width-bound FontString at the start of that line (`GameFontDisableSmall`, 10 pt, stock
  grey `GRAY_FONT_COLOR` / `W.GRAY`), capped at a fixed maximum width (about 45% of the
  Activity cell, never more than ~110 px) and cut, not wrapped; the comment follows it after a
  small gap and keeps running to the cell's right edge (still width-bound). With no zone the
  comment starts at the cell's left as today; with no comment the zone stands alone.
- **D-03:** Layout guard unchanged: no new column, no changes to the fixed left columns,
  Listed, the buttons or Activity's flexible span. Both texts on line 2 are inside the
  Activity cell and bound to it.
- **D-04:** Greyed rows (hidden, delisted, no slot for you) colour the zone like every other
  text: `W.DELISTED`.
- **D-05:** Your own listing row shows no zone (you know where you are; the row's line 2
  keeps its current content).

### What zone a row shows
- **D-06:** Solo row: the player's `area`. Group row: the leader's `area` (`l.leader.area`).
  Missing (nil / empty / secret) → no zone text, nothing else changes.

### Reading the zone safely
- **D-07:** `Listings.lua` `Member()` keeps `area` only when it is a non-secret, non-empty
  string (`Secret(p.areaName)` → nil). A secret `areaName` drops only the zone, never the
  member or the listing (unlike name/level/class/role, which skip the member). Same for
  `specName` while we are there only if trivial (it is read the same way); not required.

### Tooltip
- **D-08:** Solo tooltip: keep the existing "spec, zone" grey line (already there).
- **D-09:** Group tooltip: after the stock content, a short block listing each member whose
  zone is known: class-coloured short name, then the zone in grey (`Name  Zone` via
  `tip.line` / a double line where the tip writer supports it; otherwise "Name - Zone"),
  leader first, in member order. Members without a zone are omitted; if no member has one,
  the block (and its blank line) is omitted entirely. No new header string unless a stock
  global exists; a plain one-word label is acceptable ("Location:" / `ZONE` global if
  defined) — Claude's discretion.
- **D-10:** The full zone name is always in the tooltip (solo: the spec/zone line; group: the
  member block), so truncation in the row never hides it.

### Sorting
- **D-11:** No zone sort this phase. The header-sort system sorts by visible columns
  (Roles/Lvl/GS/Activity/Listed); the zone has no column header, so a sort would need a new
  header or a hidden modifier — not trivial. Deferred.

### Preview data
- **D-12:** `Preview.lua`: solo samples already carry zones. Group samples get member zones
  (planner picks the cheapest shape: e.g. an optional `zones` list in `extra`, or an optional
  trailing field on the member string). Include: at least one group where some members have
  no zone (omitted cleanly), one group with no zones at all (no block), and one long zone name
  (e.g. "Stranglethorn Vale" / "The Temple of Atal'Hakkar") to show truncation.
- **D-13:** `P.party` (your own group in the preview) needs no zones (D-05).

### Claude's Discretion
- Exact cap for the zone's width and the gap before the comment.
- Tooltip block label wording, and whether to use `AddDoubleLine`.
- Whether the zone/comment line uses one FontString with colour codes or two FontStrings
  (two are preferred: separate width bounds).

</decisions>

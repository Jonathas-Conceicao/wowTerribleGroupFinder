## v0.2.1 Requirements

### Damage meter (MTR)

- [x] **MTR-01**: Joining a group shows a Yes / No prompt to reset the damage meter: Details!
  when it's loaded, else the game's own meter while it's turned on; nothing is asked with neither
- [x] **MTR-02**: Entering any instance (from outside or from another instance) shows the same
  prompt; a login or `/reload` doesn't. *Adjusted (phase 12 review):* re-entering the same
  instance within 15 minutes (a run-back) doesn't ask, nor does entering an instance while
  Details! handles new-instance erase itself (its own ask / erase option)
- [x] **MTR-03**: The prompt text starts with `[TGF]`, so players know where it comes from
- [x] **MTR-04**: Each trigger can be turned on or off in Settings (Damage meter section, both on
  by default); `/tgf meter` shows the prompt now

### Region flags (REG)

- [x] **REG-05**: Flags for US, AU, EU, CN, KR and TW from the author's flagpedia.net PNGs, shown
  on rows at one height with each flag's own width (converted to the game's texture format; no
  art generated)
- [x] **REG-06**: A shard group of two letters with an optional number (`AU`, `EU`, `EU1`..`EU9`,
  `US2`, `KR1`) whose country has a flag shows that flag; the tooltip names the full group
- [x] **REG-07**: Any other shard text (e.g. `EU Paris`) shows its first two letters as text on
  the row, and the full text in the tooltip
- [x] **REG-08**: The flag-drawing script (`Media/Source/flags.js`) and its generated textures
  are removed; an internal note records that the flags come from flagpedia.net (not in the
  README)

### Spec points (SPC)

- [x] **SPC-01**: Friendly players' tooltips show their talent points per tree (e.g. `36/12/3`)
  on a line under the item level line, from the same quiet inspect item level uses; your own
  tooltip from your own talents; nothing while unknown
- [x] **SPC-02**: Spec points have their own setting in the settings page, independent of the
  item level options, on by default

### Release (REL)

- [x] **REL-06**: Release Review for v0.2.1 (code cleanup, changelog draft, the author's review
  of README and changelog), then tag `v0.2.1`
